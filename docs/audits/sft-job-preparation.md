## Changes and bounded verification

- Expanded exact-two ambiguity with an independent object tree attached only to
  the pivot. A valid witness still leaves exactly North/South or East/West.
- Constructive no-match Selection gives each candidate an exact relation other
  than the query predicate; all exclusions remain solver/certificate-checked.
- Boolean/hybrid fillers vary unrelated pair/direction choices for whole-problem
  split diversity. This does not create new core proof skeletons.
- Explicit production policies are recorded separately from historical pilot
  registry declarations. No historical result is overwritten.
- The release audit independently checks role counts, paired targets, instance
  overlap, skeleton reservations, depth limits, exact nested fractions, hashes,
  and tokenizer envelopes.
- Sealing revalidates the actual role-stratified judge sample against source
  rows. It enforces per-role and per-cell sample minima and bundles receipts
  for transferable revalidation.
- Double-rejection human appeals are packet/payload-bound and accepted only for
  eligible items. Pending appeals and quality holdouts refuse sealing.
- Jobs revalidate the bundled seal, pin model/tokenizer revision and trace
  budget, prepare matched Train/Dev views, and exclude Bench from Axolotl.
  Slurm scripts use repository-relative paths and the existing finetune
  environment; one H200 on `gpu` for three hours is the default request.
  Matching Experiment 14, every script emails BEGIN, END, FAIL, TIME_LIMIT, and
  TIME_LIMIT_90 events to `e0958116@u.nus.edu` and writes `%x-%j` logs beneath
  the prepared job directory.
  W&B online logging records training and system metrics under project
  `spatialentail-sft`, with stable arm/seed run IDs for resumed allocations;
  credentials remain external to the repository and model upload is disabled.
